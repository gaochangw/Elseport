# Elseport 管理器实现方向：待设计确认

本轮只实现可交互原型，不接入 Main API，不修改 `.xidl`，不改动运行窗口的显示或键盘实现。

## 方案比较

| 方案 | 收益 | 代价与风险 | 建议 |
| --- | --- | --- | --- |
| Qt Widgets + 统一主题层 | 可以复用现有对象、动作、翻译、测试与大部分对话框；发布依赖变化较少 | 精细排版、暗色和高 DPI 仍需主动处理；不能只靠全局样式表达成原生行为 | 第一阶段优先验证 |
| Qt Quick | 布局、状态和过渡更灵活 | 需要引入 QML 界面层、桥接对象与相应模块；控件测试及可访问性重新核查 | 仅在 Widgets 无法可靠表达关键页面时，再做小范围对照实验 |
| SwiftUI / AppKit 管理器 + 现有运行窗口 | 可以直接采用平台控件与行为 | 引入构建链、对象生命周期、跨语言/XPCOM 桥接及新的测试面；平台分支更大 | 长期候选，不在本轮凭视觉效果决定重写 |

## 推荐的接入顺序

1. 确认图形、文案、布局和默认共享策略。
2. 用现有 Qt Widgets 做一页新的管理器主页和一页安装表单，将 token 与组件集中封装；先接现有 Main 调用，不添加 API。
3. 保持现有运行窗口的画面、键盘、鼠标及宿主焦点逻辑，先调整可见工具栏与提示。
4. 测试窗口缩放、Retina、深浅外观、中文、键盘路径与 VoiceOver，证实行为之后再扩大范围。

原型不是 WebView 技术选型建议。不能把这份 HTML 直接嵌入产品来绕过原生集成和许可问题。

## 必须守住的边界

共享默认关闭属于本轮设计建议，尚未改变产品行为。产品实现时需同步更新说明与已有测试。

无缝布局、全屏、恢复点、虚拟电脑关机与保存均要从现有接口接入，并验证真实行为。浏览器里可点击不等于产品完成。

新增 UI 如果基于已修改的本项目代码，继续按 GPLv3 处理；换语言或界面技术不是闭源许可方案。Qt 及其插件应按实际分发配置重新核对。

本轮不需要大规模重命名内部 `VBox*` 标识，也不触碰配置迁移、IPC 隔离、驱动或固件。它们属于后续经验证的品牌接入和工程阶段。
